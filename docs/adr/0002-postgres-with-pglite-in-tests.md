# 2. PostgreSQL in production, PGlite in tests and local runs

Date: 2026-11-01. Status: accepted.

## Context

Odds snapshots grow by hundreds of rows per poll and will reach millions. A dashboard will read while the worker
writes. Tests should exercise the real SQL (constraints, `on conflict`, `distinct on`), and the laptop has no
Docker.

## Decision

PostgreSQL 18 in production, through Drizzle ORM with SQL migrations generated by drizzle-kit. Tests and local runs
use PGlite, the Postgres engine compiled to WebAssembly and run in-process. A CI job runs the repository tests again
against a real Postgres 18 service, and the Docker smoke test boots the production stack.

## Consequences

- Rules the data must never break live in the schema: odds above 1, positive stakes, a score exactly when a
  fixture is finished, `settled_at` exactly when a bet is settled, one bet per player and selection.
- Test suites open one database per file and truncate between tests: the whole suite runs in seconds.
- PGlite and the production driver can differ at the edges: the Postgres job caught a raw-SQL date parameter that
  PGlite accepted and postgres.js rejected. Typed query operators avoid that class of bug.
